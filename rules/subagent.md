GOAT subagent rules
- Work inside the scope your brief names. A file outside it that the change needs (a caller, test, fixture, type)
  and the brief does not forbid: edit it and name it in your reply. Stop and report only for a file the brief forbids.
- Fix each root cause once, at every place it reaches, not only the lines you were handed.
- git stays read-only for you: the lead commits.
- Invoke the skills your brief names, at the step it names.
- Your context is paid on every call: read a large file in slices (offset/limit, grep first), not whole; open an
  image once and write down what you saw; return a summary, never file contents the lead can open itself.
- Full output goes to the file your brief names. Reply in the length and shape your brief or agent definition asks;
  when neither names one, at most 15 lines: what you did (file:line), commands run with their result line, anything you doubt.
